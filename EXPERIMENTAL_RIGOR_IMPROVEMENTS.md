# Experimental Rigor Improvements

## Overview

This document describes improvements made to the AI Scientist software to address common weaknesses identified in peer reviews of generated papers. The improvements focus on **experimental rigor** - ensuring papers meet top-tier publication standards by avoiding common pitfalls.

## Problem: Common Review Weaknesses

Based on actual reviewer feedback, papers generated by AI systems often suffer from:

### 1. **Reliance on Synthetic-Only Evaluation**
- **Issue**: Papers test methods only on toy/synthetic datasets
- **Reviewer Concern**: "The empirical results are based entirely on synthetic evaluation... fails to demonstrate efficacy on real-world, complex tasks"
- **Impact**: Rejection - reviewers cannot assess practical applicability

### 2. **Unvalidated Core Assumptions**
- **Issue**: Papers assume properties (e.g., submodularity, diminishing returns) without empirical validation
- **Reviewer Concern**: "It is an open question whether complex reasoning adheres strictly to this. 'Eureka' moments would violate this assumption"
- **Impact**: Weakness - theoretical contributions lack empirical grounding

### 3. **Missing Complexity Analysis**
- **Issue**: No computational overhead measurements or Big-O notation
- **Reviewer Concern**: "The computational overhead... must be carefully accounted for, especially in low-latency applications"
- **Impact**: Major revision - reviewers cannot assess practical feasibility

### 4. **Excessive Algorithm Density**
- **Issue**: Too many methods (e.g., 10 algorithms) without comprehensive evaluation
- **Reviewer Concern**: "Overwhelming amount for a single paper... analysis necessarily shallow, with eight of ten algorithms receiving no empirical evaluation"
- **Impact**: Unfocused paper, superficial analysis

### 5. **Poor Calibration Awareness**
- **Issue**: Relying on LLM confidence without addressing known calibration problems
- **Reviewer Concern**: "LLMs are often poorly calibrated, and obtaining reliable estimates is a major open research problem"
- **Impact**: Fundamental method flaw if confidence estimates are unreliable

## Solution: Multi-Layered Validation System

### Layer 1: Automated Detection (`utils/experimental_rigor_validator.py`)

New validation module that automatically detects common issues:

#### **Synthetic-Only Evaluation Detector**
```python
def detect_synthetic_only_evaluation(paper_content: str, sim_summary: str) -> List[str]
```
- Scans for synthetic data indicators: "synthetic data", "toy problem", "simulated environment"
- Scans for real-world dataset mentions: "ImageNet", "GLUE", "WikiText", standard benchmarks
- **Triggers**: If >2 synthetic mentions and 0 real-world mentions
- **Output**: "CRITICAL: Paper appears to rely entirely on synthetic/toy evaluation. Add real-world benchmark evaluation..."

#### **Unvalidated Assumptions Detector**
```python
def detect_unvalidated_assumptions(paper_content: str) -> List[str]
```
- Finds assumption statements: "we assume", "under the assumption", "Assumption 1:"
- Checks for validation experiments: "validating the assumption", "empirical verification"
- **Triggers**: If >2 assumptions without validation section
- **Special Check**: Submodularity assumptions without empirical tests
- **Output**: "CRITICAL: Paper makes N assumptions but does not empirically validate them..."

#### **Missing Complexity Analysis Detector**
```python
def detect_missing_complexity_analysis(paper_content: str, sim_summary: str) -> List[str]
```
- Counts algorithms proposed: `\begin{algorithm}`, `Algorithm N:`
- Checks for complexity notation: "time complexity", "O(n)", Big-O patterns
- Checks for overhead measurements: "runtime", "latency", "wall-clock time"
- **Triggers**: If algorithms exist without complexity analysis
- **Special Check**: Metareasoning methods without scheduler overhead measurement
- **Output**: "CRITICAL: Paper proposes N algorithm(s) but lacks complexity analysis..."

#### **Algorithm Density Detector**
```python
def detect_algorithm_density_issues(paper_content: str) -> List[str]
```
- Counts total algorithms/methods: algorithm blocks + named methods (acronyms)
- Checks which methods appear in Results section (empirically evaluated)
- **Triggers**: If >5 methods total, or >50% unevaluated
- **Output**: "CRITICAL: Paper proposes N methods but only M empirically evaluated..."

#### **Poor Calibration Detector**
```python
def detect_poor_calibration_issues(paper_content: str) -> List[str]
```
- Detects calibration reliance: "self-evaluation", "confidence score", "LLM calibration"
- Checks if calibration challenges are discussed
- Checks if calibration is measured: "ECE", "calibration curves", "Brier score"
- **Triggers**: If using calibration without discussing challenges or measuring quality
- **Output**: "CRITICAL: Paper relies on LLM confidence but does not discuss calibration challenges..."

### Layer 2: Enhanced Prompts

#### **Review Prompt Enhancements**

Added section "🔬 EXPERIMENTAL RIGOR REQUIREMENTS (CRITICAL FOR PUBLICATION)":

```
1. SYNTHETIC-ONLY EVALUATION WEAKNESS:
   - Papers relying entirely on synthetic/toy datasets will be rejected
   - MUST include real-world benchmark evaluation
   
2. UNVALIDATED ASSUMPTIONS:
   - Papers making critical assumptions MUST validate them
   - Require ablation studies testing whether assumptions hold
   
3. MISSING COMPLEXITY ANALYSIS:
   - ALL proposed algorithms MUST include complexity analysis
   - Empirical overhead measurements required
   
4. ALGORITHM DENSITY (OVERWHELMING SCOPE):
   - Proposing >5 algorithms suggests insufficient depth
   - EACH algorithm should have theoretical analysis + empirical validation
   
5. CALIBRATION AND SELF-EVALUATION:
   - If using LLM confidence, MUST acknowledge calibration challenges
   - Should measure calibration quality (ECE, calibration curves)
   
6. STATISTICAL RIGOR:
   - Report mean, std dev, confidence intervals
   - Multiple seeds/runs required
   
7. HONEST LIMITATIONS:
   - Discuss when methods may fail
   - Acknowledge synthetic vs real-world gaps
```

#### **Revision Prompt Enhancements**

Added actionable revision guidance:

```
1. AVOID SYNTHETIC-ONLY EVALUATION:
   - ADD real-world benchmark experiments
   - Use standard datasets: ImageNet, CIFAR, GLUE, SQuAD...
   
2. VALIDATE YOUR ASSUMPTIONS:
   - For each assumption, ADD validation experiments
   - Include ablation studies
   - DISCUSS when assumptions may break
   
3. ADD COMPLEXITY ANALYSIS:
   - Provide Big-O notation for ALL algorithms
   - Measure empirical overhead vs baselines
   
4. REDUCE ALGORITHM DENSITY OR INCREASE DEPTH:
   - If >5 algorithms: reduce to 2-4 or move others to appendix
   - EVERY algorithm needs full evaluation
   
5. ADDRESS CALIBRATION CHALLENGES:
   - ACKNOWLEDGE LLMs are poorly calibrated
   - Measure ECE, calibration curves, Brier score
   
6. ENSURE STATISTICAL RIGOR:
   - Report mean ± std across multiple runs
   - Statistical significance tests
   
7. PROVIDE HONEST LIMITATIONS:
   - Discuss when method fails
   - Be transparent about scope
```

#### **Combined Review+Revision Prompt**

Added checklist format:

```
🔬 EXPERIMENTAL RIGOR CHECKLIST:
1. ❌ Synthetic-only evaluation → ✓ Add real-world benchmark validation
2. ❌ Unvalidated assumptions → ✓ Include ablation studies
3. ❌ Missing complexity analysis → ✓ Provide Big-O and overhead
4. ❌ Too many algorithms → ✓ Focus on 2-4 with depth
5. ❌ Ignoring calibration → ✓ Acknowledge, measure ECE
6. ❌ Weak statistics → ✓ Multiple runs, significance tests
7. ❌ Hiding limitations → ✓ Honest discussion
```

### Layer 3: Workflow Integration

Modified `sciresearch_workflow.py` to run validation during paper iteration:

```python
# EXPERIMENTAL RIGOR VALIDATION
from utils.experimental_rigor_validator import validate_experimental_rigor
rigor_critical, rigor_warnings = validate_experimental_rigor(
    current_tex,
    sim_summary,
    project_dir=project_dir
)

# Add critical issues to quality_issues (blocks iteration)
quality_issues.extend(rigor_critical)

# Log warnings (doesn't block but shows to user)
if rigor_warnings:
    print(f"⚠ Experimental rigor warnings ({len(rigor_warnings)} total):")
    for idx, warning in enumerate(rigor_warnings[:5], 1):
        print(f"   {idx}. {warning}")
```

## Benefits

### 1. **Early Detection**
- Issues caught during generation, not after submission
- Automated validation runs every iteration
- Saves time compared to post-review fixes

### 2. **Actionable Guidance**
- Specific, concrete suggestions: "Add ImageNet experiments", "Measure ECE"
- Not just "improve rigor" - tells HOW to improve
- Examples provided in prompts

### 3. **Publication-Ready Papers**
- Addresses real reviewer concerns (from actual reviews)
- Meets top-tier venue standards (Nature, Science, ICML, NeurIPS)
- Reduces revision cycles

### 4. **Educational Value**
- Users learn what rigorous research requires
- Prompts teach best practices
- Builds better research intuition

```
CRITICAL: Paper appears to rely entirely on synthetic/toy evaluation. 
Add real-world benchmark evaluation to demonstrate practical applicability. 
Reviewers expect validation on standard benchmarks (e.g., ImageNet, GLUE) 
to show the method works beyond idealized synthetic settings.
```

**Revision Guidance**:
```
ADD real-world benchmark experiments:
- Use ImageNet for vision tasks
- Use GLUE/SQuAD for NLP tasks
- If only synthetic: acknowledge limitation explicitly
```

### Example 2: Detecting Unvalidated Assumptions

**Input Paper**:
```latex
\textbf{Assumption 1}: The reasoning process exhibits submodularity...

We assume that deliberation has diminishing returns...

```

**Validation Output**:
```
CRITICAL: Paper makes 3 explicit assumptions but does not appear to 
empirically validate them. Reviewers expect ablation studies testing 
whether key assumptions actually hold in practice.

WEAKNESS: Paper assumes submodularity/diminishing returns but does not 
empirically verify this holds. Reviewers will question whether 'Eureka 
moments' violate this assumption. Add experiments measuring submodularity.
```

**Validation Output**:
```
CRITICAL: Paper proposes 2 algorithms but lacks complexity analysis.

overhead measurements. Add theoretical complexity analysis and empirical
```
