# Summary: Experimental Rigor Improvements for AI Scientist

## What Was The Problem?

Based on actual reviewer feedback, papers generated by AI systems often get rejected for **experimental rigor issues**:

### Actual Review Quote:
> "While the paper is theoretically strong, it faces challenges regarding practical applicability:
> 1. **Reliance on Synthetic Evaluation** - fails to demonstrate efficacy on real-world tasks
> 2. **Unvalidated Assumptions** - submodularity may not hold, 'Eureka moments' violate this
> 3. **Missing Complexity Analysis** - computational overhead must be carefully accounted for
> 4. **Excessive Density** - 10 algorithms, shallow analysis, 8 receive no evaluation
> 5. **Calibration Challenges** - LLMs are poorly calibrated, estimates may be unreliable"

These are **not unique issues** - they appear across many AI-generated papers and lead to rejection.

## What Did We Build?

A **3-layer validation system** that catches and fixes these issues **before submission**:

### Layer 1: Automated Detection
**New file**: `utils/experimental_rigor_validator.py`

5 smart detectors that scan papers for common problems:

1. **`detect_synthetic_only_evaluation()`**
   - Scans for "synthetic data", "toy problem", "simulated environment"
   - Checks for real benchmarks: "ImageNet", "GLUE", "WikiText"
   - **Triggers**: >2 synthetic mentions, 0 real-world mentions
   - **Output**: "CRITICAL: Add real-world benchmark validation"

2. **`detect_unvalidated_assumptions()`**
   - Finds: "we assume", "Assumption 1:", "under the assumption"
   - Checks for validation: "validating the assumption", "ablation"
   - **Special check**: Submodularity without empirical tests
   - **Output**: "CRITICAL: N assumptions without validation"

3. **`detect_missing_complexity_analysis()`**
   - Counts algorithms: `\begin{algorithm}`, `Algorithm N:`
   - Checks for: "Big-O", "time complexity", "overhead"
   - **Triggers**: Algorithms without complexity analysis
   - **Output**: "CRITICAL: Lacks complexity analysis"

4. **`detect_algorithm_density_issues()`**
   - Counts total methods/algorithms
   - Checks which are actually evaluated in Results
   - **Triggers**: >5 methods or >50% unevaluated
   - **Output**: "CRITICAL: N methods but only M evaluated"

5. **`detect_poor_calibration_issues()`**
   - Detects: "self-evaluation", "confidence score", "calibration"
   - Checks if calibration challenges discussed
   - Checks if measured: "ECE", "Brier score"
   - **Output**: "CRITICAL: Relies on calibration without discussion"

### Layer 2: Enhanced Prompts
**Modified file**: `sciresearch_workflow.py`

Added to **review prompt** (what reviewer sees):
```
🔬 EXPERIMENTAL RIGOR REQUIREMENTS:
1. SYNTHETIC-ONLY WEAKNESS → MUST include real-world benchmarks
2. UNVALIDATED ASSUMPTIONS → Require ablation studies
3. MISSING COMPLEXITY → Big-O notation + overhead measurements required
4. ALGORITHM DENSITY → >5 algorithms suggests insufficient depth
5. CALIBRATION ISSUES → Must acknowledge LLM miscalibration
6. STATISTICAL RIGOR → Mean, std dev, significance tests
7. HONEST LIMITATIONS → Discuss when methods fail
```

Added to **revision prompt** (how to fix):
```
1. ADD real-world benchmark experiments (ImageNet, GLUE, WikiText)
2. VALIDATE assumptions with ablation studies
3. PROVIDE Big-O notation and measure overhead
4. REDUCE to 2-4 core methods with comprehensive evaluation
5. ACKNOWLEDGE calibration challenges, measure ECE
6. ENSURE statistical rigor: multiple runs, confidence intervals
7. PROVIDE honest limitations discussion
```

Added to **combined prompt** (quick checklist):
```
❌ Synthetic-only → ✓ Add real-world benchmarks
❌ Unvalidated assumptions → ✓ Ablation studies
❌ No complexity → ✓ Big-O + overhead
❌ Too many algorithms → ✓ Focus 2-4 with depth
❌ Ignore calibration → ✓ Acknowledge + measure
❌ Weak statistics → ✓ Multiple runs + tests
❌ Hide limitations → ✓ Honest discussion
```

## Real Examples

### Example 1: Catches Synthetic-Only Papers
**Paper says**:
```latex
We evaluate on synthetic datasets with randomly generated instances.
The synthetic benchmark consists of 1000 toy problems...
```

**Validator catches**:
```
CRITICAL: Paper appears to rely entirely on synthetic/toy evaluation.
Add real-world benchmark evaluation (ImageNet, GLUE, WikiText) to
demonstrate practical applicability beyond idealized settings.
```

**LLM fixes** (in revision):
```latex
We evaluate on both synthetic and real-world benchmarks:
1. Synthetic: Controlled validation (1000 instances)
2. Real-world: ImageNet-1K, CIFAR-100, WikiText-103

Results show our method achieves 85.3% on ImageNet...
```

### Example 2: Catches Unvalidated Assumptions
**Paper says**:
```latex
\textbf{Assumption 1}: The reasoning process exhibits submodularity.
We assume that deliberation has diminishing returns.
```

**Validator catches**:
```
CRITICAL: Paper makes 2 assumptions but does not empirically validate them.
Add ablation studies testing whether assumptions hold in practice.

WEAKNESS: Assumes submodularity without verification. Reviewers will
question whether 'Eureka moments' violate this assumption.
```

**LLM fixes**:
```latex
\subsection{Assumption Validation}
We empirically test the submodularity assumption by measuring
marginal gains: Δf(S∪{x}) = f(S∪{x}) - f(S)

Figure 3 shows marginal gains decrease as |S| increases, supporting
submodularity. However, we observe violations in 8% of cases,
typically when breakthrough insights occur...

\subsection{Limitations}
Our submodularity assumption holds for 92% of reasoning chains but
can be violated by sudden "Eureka moments"...
```

### Example 3: Catches Missing Complexity
**Paper proposes** 3 algorithms without analysis

**Validator catches**:
```
CRITICAL: Paper proposes 3 algorithms but lacks complexity analysis.
Add Big-O notation and measure empirical overhead vs baselines.
```

**LLM fixes**:
```latex
\subsection{Complexity Analysis}
Algorithm 1 (BPF): O(n log n) time, O(n) space
Algorithm 2 (MVC): O(n²) time, O(n) space
Algorithm 3 (IGD): O(n) time, O(n) space

\subsection{Empirical Overhead}
Table 2 shows wall-clock time comparison:
Method        | Runtime (ms) | Overhead vs Baseline
--------------|--------------|---------------------
Baseline (CoT)| 145 ± 12    | —
BPF           | 167 ± 15    | +15%
MVC           | 198 ± 22    | +37%
IGD           | 156 ± 11    | +8%
```

```

Output shows warnings:
```

### Manual Validation
Can also validate papers directly:
```python

paper = open("paper.tex").read()
results = open("results.txt").read()

critical, warnings = validate_experimental_rigor(paper, results)
print(f"Issues: {len(critical)} critical, {len(warnings)} warnings")
```

## Success Metrics

A **publication-ready** paper should have:
- ✅ 0 critical experimental rigor issues
- ✅ ≤2 experimental rigor warnings
- ✅ Real-world benchmark results (not just synthetic)
- ✅ Empirical validation of key assumptions
- ✅ Complexity analysis (Big-O) for all algorithms
- ✅ 2-4 core methods with comprehensive evaluation
- ✅ Calibration discussion if using confidence scores
- ✅ Statistical rigor (mean ± std, multiple runs)
- ✅ Honest limitations section
